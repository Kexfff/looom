# Команда rebuild

Дата: 2026-10-11. Добавлена нативная Rust-команда:

```sh
sudo looom rebuild ~/looom/base.yaml desktop-next
```

Она выполняет `check → lock → build → publish → try`, показывает текущий этап
и останавливается при первой ошибке. Декларация и содержимое её файлов читаются
один раз. Имя релиза проверяется до разрешения пакетов и повторно перед сборкой.
Resolver использует свою штатную блокировку; затем сборка, публикация и выбор
пробной загрузки выполняются под общей блокировкой управления релизами.
Автоматической перезагрузки и подтверждения нет. Отдельные команды сохранены.

## VM и Rust

Сборки и тесты выполнялись только в `Cachyos`, MAC `52:54:00:7b:23:63`,
UEFI/KVM, 6 vCPU/8 GiB, Btrfs vda 60 GiB. Подтверждённый рабочий корень
`rust-gc-ready` оставался read-only и не менялся. Сохранённый toolchain
`@toolchain-20261006` смонтирован в `/var/lib/looom/dev/root`; исходники
`/var/lib/looom/dev/src` подключены внутрь как `/workspace`.

```sh
arch-chroot /var/lib/looom/dev/root bash -c '
  cd /workspace &&
  cargo fmt &&
  cargo clippy --locked --all-targets -- -D warnings &&
  LOOOM_TEST_VM=1 cargo test --locked -- --nocapture --test-threads=1 &&
  cargo build --locked --release --bin looom
'
python3 /var/lib/looom/dev/src/scripts/test-rebuild.py
```

Clippy прошёл без предупреждений, все 12 Rust-тестов прошли, release-бинарник
собран. [Rust-журнал](rust-final.log), [контроллер](../../../scripts/test-rebuild.py),
[журнал CLI и сборок](rebuild.log), [SHA исходников](source.sha256),

## Реальная цепочка и ошибки

Контроллер проверяет root, конкретный MAC, виртуализацию и read-only корень.
Ошибочная схема YAML, неверные аргументы/ID и занятое имя релиза отклоняются
до создания lock или сборки. Отсутствующий официальный пакет останавливает
`lock`: private build не создаётся. В обоих случаях `saved_entry` и `next_entry`
сохранены.

Для `rebuild-interrupted-20261011` выполнена настоящая установка пакетов
console-профиля с инъекцией `LOOOM_FAIL_AFTER=build-packages`. Команда завершилась
на третьем этапе; private build остался в фазе `building`, metadata релиза и
публичный UKI не появились. Публикация и выбор пробной загрузки не запускались.
Приватные входы и root оставлены для диагностики на development VM.

Успешный `rebuild-desktop-20261011` прошёл все пять этапов. Получены **677
подписанных пакетов** Arch на дату `2026-10-07`, включая Plasma и SDDM,
read-only Btrfs root, опубликованный UKI и `next_entry=looom-rebuild-desktop-20261011`.
Проверены точное совпадение frozen lock, содержимое объявленного файла,
SHA установленного менеджера и опубликованного UKI. YAML находился в каталоге
с пробелом в имени. Временные ключи проверки SSH отсутствуют в готовом root;
предупреждения `Unable to load host key` не возникли.

`saved_entry=looom-rust-gc-ready`, boot ID и запущенный релиз остались прежними.
После проверки контроллер восстановил исходный пустой `next_entry`, сохранив
published-кандидат для будущего ручного испытания. Новый релиз в этом прогоне
не загружался; повторная GUI-приёмка не заявляется.
[Машинный результат](rebuild-result.json).

Публичные журналы проверены на исходной VM до экспорта на отсутствие её
credentials: [аудит](public-audit.log). На диске осталось около 22 GiB свободного
места. Toolchain размонтирован; development VM возвращена в выключенное состояние.
Локально выполнялись только чтение, редактирование, передача файлов и сравнение
SHA. Пользовательская VM и Intel N100 не изменялись.

Готовый бинарник сохранён локально как
`.local/artifacts/looom-0.2.0-rebuild-20261011-x86_64`. Опубликованный ISO
`v0.2.0-alpha.1` не пересобирался и содержит прежний менеджер без `rebuild`.
