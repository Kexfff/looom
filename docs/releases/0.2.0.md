# looom 0.2.0

Первый полный выпуск для повседневного тестирования: готовый установочный ISO,
KDE Plasma, отдельный слой приложений и нативное управление системой на Rust.
Поддерживаемый путь — официальный Arch, x86_64/UEFI, отдельный диск целиком,
Btrfs, один пользователь, без шифрования и Secure Boot.

[Скачать выпуск](https://github.com/Kexfff/looom/releases/tag/v0.2.0),
[установка и обновление alpha](../live-iso.md),
[журнал приёмки](../runs/2026-10-12-release-0.2.0/README.md).

## Что входит

- Установочный и аварийный ISO с готовым looom: меню, сеть, выбор диска по номеру,
  простое подтверждение `YES`, скрытый ввод собственных паролей.
- Limine и отдельный UKI каждого системного релиза. Read-only корень,
  пробная загрузка, ручное подтверждение, возврат к подтверждённому релизу,
  recovery и сборка новых релизов без изменения работающего корня.
- `looom rebuild ~/looom/base.yaml desktop-next`: check, lock, build, publish,
  try в одной команде. При ошибке цепочка останавливается; reboot остаётся явным.
- KDE с сетью, PipeWire, Bluetooth, управлением питанием, polkit и portals;
  Dolphin, Konsole, Ark, Kate, Spectacle, emoji-шрифты.
- `looom setup` в меню KDE и при первом входе: подтвердить проверенную систему,
  установить приложения, сменить пароль, собрать релиз или посмотреть очистку.
  Привилегированные действия требуют sudo; показ меню ничего не устанавливает
  и не подтверждает. Повторный вход не открывает его снова.
- Доступные пользователю `~/looom/base.yaml`, `base.lock`, `apps.yaml`.
  Новая декларация приложений содержит Firefox; применение выполняется
  отдельно от пользователя. Существующие декларации не переписываются.
- Flatpak, rootless Arch/Distrobox, AppImage с проверкой SHA256 и desktop-launcher.
  `.sh` через `looom apps run-script` выполняются в контейнере; bare pacman
  и `sudo /usr/bin/pacman` работают там. Системные зависимости можно импортировать
  в декларацию; Niri/iNiR остаётся отдельным проверенным профилем после установки.
- Нативные credentials, восстановление незавершённых операций и GC.
  Очистка сохраняет работающий, выбранный и необходимые подтверждённые релизы,
  пользовательские приложения и HOME.

## После установки

Загрузиться с диска, войти в KDE, проверить рабочий стол, сеть и звук.
В «Настройке looom» выбрать подтверждение системы, затем установку приложений.
Firefox потребует интернет. Мастер можно снова открыть командой `looom setup`.

```sh
# Изменение системы: отредактировать ~/looom/base.yaml, затем
sudo looom rebuild ~/looom/base.yaml desktop-next
sudo reboot
# После проверки нового рабочего стола:
sudo looom verify
sudo looom confirm

# Приложения не требуют пересборки корня:
looom apps apply
looom apps update

# Сначала посмотреть список очистки:
sudo looom gc --keep 3
```

Откат системы сохраняет пароль, HOME, пользовательские приложения и явно
разрешённые локальные настройки. Он не отменяет обновления приложений и правки
пользовательской конфигурации рабочего стола. Снимок на том же диске не заменяет backup.

## Границы выпуска

Установка через интернет, консольный live ISO, KDE — единственный вариант
в установщике. Calamares, CachyOS, dual boot, шифрование, Secure Boot,
многопользовательская декларация и универсальная поддержка оборудования — дальше.
AppImage не является песочницей; Distrobox интегрирован с HOME, поэтому запускать
следует доверенные скрипты. Host-only systemd/udev/драйверные установщики нельзя
целиком перенести в контейнер. GUI смена пароля через обычный `passwd` пока
не поддерживается: используйте `looom setup` или `sudo looom password <user>`.

Системные пакеты фиксируются подписанным Arch Archive `2026-10-07` и lock.
Flatpak/контейнеры обновляются отдельно и не имеют общего атомарного rollback.
Манифест ISO фиксирует входы сборки; идентичность повторных ISO байт в байт
не заявляется. Новый выпуск проверен в VM; прежний пилот N100 описан отдельно,
он не заменяет проверку этого ISO на другом железе.
