# looom 0.2.0

The first complete release for everyday testing includes an installation ISO,
KDE Plasma, separate user applications, and native Rust system management.
[Download](https://github.com/Kexfff/looom/releases/tag/v0.2.0) ·
[Installation and alpha upgrades](../live-iso.md) ·
[Validation evidence](../runs/2026-10-12-release-0.2.0/README.md)

## Included

- Online installer/rescue ISO with looom already present: numbered disk choice,
  `YES` confirmation, hidden custom passwords, automatic partitioning and setup.
- Limine, per-release UKIs, read-only Btrfs roots, trial boots, confirmation,
  rollback, recovery, and native garbage collection.
- `looom rebuild <base.yaml> <id>` combining check, lock, build, publish, and try;
  explicit reboot and confirmation.
- KDE with networking, PipeWire, Bluetooth, power management, polkit, portals,
  Dolphin, Konsole, Ark, Kate, Spectacle, and emoji fonts.
- `looom setup` at first login and in the KDE menu: explicit confirmation,
  Firefox installation, application updates, passwords, rebuilding, and maintenance.
- User-owned `~/looom/base.yaml`, `base.lock`, and `apps.yaml`.
- Flatpak, rootless Arch/Distrobox, verified AppImages, and container installer
  scripts. Niri/iNiR remains an optional profile installed after KDE setup.

All builds and tests ran in VMs: Clippy passed without warnings, 12 Rust tests
passed, and real ISO installation, KDE/Firefox, container scripts, AppImage,
trial fallback, rollback, GC, and password persistence were exercised.

## Scope

Official Arch, x86_64/UEFI, a whole disk, Btrfs, one managed user. The installer
provides only KDE. Internet is required; the ISO is a console environment.
Encryption, Secure Boot, dual boot, CachyOS, and Calamares remain future work.
New hardware acceptance remains separate from the VM results.

System rollback preserves passwords, HOME, applications, and explicit local
settings. It does not roll back application updates or personal desktop changes.
Use native password commands; standard `passwd` and GUI password changes are
unsupported. AppImage is not a sandbox, and Distrobox shares HOME.

System inputs use the signed Arch Archive snapshot `2026-10-07` and a lock.
Application sources update independently. Reproducibility means fixed inputs
and verified composition, not a promise of byte-identical ISO/UKI rebuilds.
